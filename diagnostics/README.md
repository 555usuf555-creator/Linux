# server-check.sh — разовая диагностика сервера

> **Статус:** проверено на ALT Linux 10.4 (Mendelevium), ядро 6.1.124.
> Дата проверки: 1 октября 2026.

Скрипт показывает состояние сервера и **ничего не меняет**. Он нужен, когда
непонятно, где именно сломано: в инструкциях предполагается, что проблема уже
известна, а чаще всего она как раз неизвестна.

## Установка и запуск

```bash
$ git clone https://github.com/555usuf555-creator/Linux.git
$ cd Linux/diagnostics
$ chmod +x server-check.sh
$ sudo ./server-check.sh
```

**Нужен `root`.** Часть проверок читает эффективные параметры `sshd`
(`/usr/sbin/sshd -T`), содержимое `/etc/shadow` и правила `iptables` — без
привилегий они недоступны. Без `root` скрипт не падает, а показывает меньше.

### Код возврата

| Код | Значение |
|---|---|
| `0` | критичных ошибок нет, есть только предупреждения |
| `1` | найдена хотя бы одна ошибка уровня `ОШИБКА` |

Пригоден для cron и для проверок в скриптах развёртывания.

## Что проверяется

### 1. Система

Диск (`df -h`), inode (`df -i`), память, ядро, время работы.

Пороги: диск и inode — 75 % (предупреждение) и 90 % (ошибка), память — 90 %.

Отдельно проверяются inode, потому что система может упереться не в мегабайты,
а в число файлов, и тогда `Avail` большой, а писать всё равно некуда.

### 2. Сеть и открытые порты

Считает слушающие сокеты и разделяет их на loopback (снаружи недоступны) и
те, что слушают на всех интерфейсах. Показывает список последних — это и есть
потенциально открытая поверхность.

Пытается определить внешний адрес через `api.ipify.org`. Если интернета нет,
строка сообщает об этом и проверка не считается ошибкой.

### 3. SSH

Конфиг ищется по двум путям: `/etc/openssh/sshd_config` и `/etc/ssh/sshd_config`.

> **Ловушка ALT.** Правильный путь на ALT — `/etc/openssh/sshd_config`.
> Пути `/etc/ssh/sshd_config` на ALT **нет вообще**. Большинство инструкций
> в интернете пишут именно `/etc/ssh/…`, и на ALT это приводит к ошибке
> «нет такого файла», которую принимают за поломку системы.

Проверяются не строки в файле, а **эффективные значения** через `sshd -T`.
Это важно: в конфиге параметр может быть задан несколько раз, и
`sshd -T` показывает то, что реально применится.

| Параметр | Критерий |
|---|---|
| `passwordauthentication` | `yes` → ошибка |
| `pubkeyauthentication` | `no` → ошибка |
| `kbdinteractiveauthentication` | `yes` → предупреждение |
| `permitrootlogin` | `yes` → ошибка; `without-password`/`no` → предупреждение |
| неудачные входы по паролю за сутки | больше 20 → предупреждение + топ адресов |

### 4. Права и sudo

`visudo -c` должен разбирать все файлы без ошибок. Затем проверяются права
файлов в `/etc/sudoers.d/`.

> **Ловушка ALT.** ALT требует права **0400** на файлах в `/etc/sudoers.d/`.
> В Debian и RHEL ставят 0440. При 0440 ALT отказывается работать, и
> `sudo` перестаёт видеть правила — с сообщением, которое не указывает на
> реальную причину.

Предупреждения самого `visudo` (например, `unused User_Alias`) выводятся
дополнительно: это не ошибка, но полезно знать.

### 5. Службы

Упавшие службы (`systemctl list-units --state=failed`), количество работающих,
размер журнала (`journalctl --disk-usage`) с порогом 60 % и 85 % от файловой
системы, и число открытых удалённых файлов.

Последнее — файлы, которые удалены с диска, но всё ещё держатся процессами.
Место под них не освободится, пока не закроется последний держатель. Скрипт
подсказывает `lsof +L1`.

### 6. Безопасность

SELinux, отсутствие файрвола (`firewalld`, `nftables`, `ufw`), состояние
`iptables`, учётки без пароля, `uid 0` у обычных пользователей, число
неудачных попыток входа.

**Учётки без пароля** ловятся только по пустому полю:

```bash
$2==""      # правильно
($2==""||length($2)<2)   # неправильно - ловит и заблокированные
```

У системных учёток в поле пароля стоит `!` или `*` — это «учётка
заблокирована», а не «пароля нет». Проверка, ловящая любой пароль короче двух
символов, ругается почти на все учётки системы и через неделю её
игнорируют вместе с настоящими находками.

`uid 0` у кого-то, кроме `root`, — всегда ошибка: это равнозначный доступ.

### 7. Обновления и время

Неустановленные обновления (`apt-get -s upgrade`) и состояние синхронизации
времени (`chronyc`).

Состояние времени читается так:

```bash
chronyc tracking | sed -n 's/^Leap status[[:space:]]*:[[:space:]]*//p'
```

Номер поля брать нельзя: строка выглядит `Leap status     : Normal`, и
`awk '{print $3}'` выдаёт двоеточие. При `Not synchronised` слов больше, и
значение съедет на другой номер.

## Известные проблемы и ограничения

| Что | Как обойти |
|---|---|
| Без `root` часть проверок молча пропускается | Запускать через `sudo` |
| Нет `curl` или нет интернета — не определяется внешний адрес | Не ошибка, информационная строка |
| Нет `chronyc` — проверка времени пропускается целиком | Установить `chronyc` |
| Нет `lsof` — не видно открытых удалённых файлов | Установить `lsof` |
| Предупреждение может быть ложным | **Всегда проверять находку вручную перед исправлением** |

Последняя строка — не формальность. Скрипт однажды указал, что `root` может
войти по ключу; при проверке оказалось, что `authorized_keys` содержит только
закомментированную заглушку из образа и ключа там нет вовсе.

## Чего скрипт не делает

- Не меняет ни одного файла
- Не перезапускает ни одной службы
- Не правит права
- Не закрывает и не открывает порты

Это намеренно. Скрипт, который попутно всё «исправляет», способен закрыть
SSH посреди сессии. Диагностика должна быть безобидной: исправлять вы
будете сами, зная, где именно.

## Установка в cron

Раз в сутки, отправлять только при наличии ошибок:

```cron
17 8 * * * root /opt/server-check.sh | grep -q 'ОШИБКА' && \
        mail -s 'Ошибки на сервере' root@localhost
```

Обратите внимание: скрипт печатает `ОШИБКА` и `ВНИМАНИЕ`, и для cron
разумно реагировать именно на `ОШИБКА` — предупреждения иначе придут
каждый день и перестанут читаться.
